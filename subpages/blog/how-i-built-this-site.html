How I built this site

2026-10-22 2 min read #tech
all posts

When I started this site, I had two rules: it had to cost nothing, and it had to feel like me. Here's how it came together.

No frameworks, just files

The whole site is plain HTML, CSS and a little bit of JavaScript. No React, no build step, no npm install that pulls in half the internet. Every page is just a file in a folder, so when something looks off, I open the file and fix it. For a personal site with a handful of pages that felt like the right call, and honestly it was a nice change from school projects where the setup takes longer than the actual work.

Hosting on GitHub Pages

The code lives in a GitHub repository, and GitHub Pages serves it straight from there. It's free, there's no server for me to maintain, and publishing an update is just a push:

A minute later the change is live. As a student who already spends enough on coffee, free hosting with zero maintenance is hard to beat.

A theme that feels like a terminal

I'm into backend development, so I wanted the site to feel like something a developer would build, not a generic portfolio template. That's why there are monospace labels everywhere, paths like ~/blog in the page headers, and a little GET /api/me response on the homepage that introduces me as JSON. My contact info even starts with $ ./contact.sh. Small details, but they make browsing the site feel a bit like poking around in a terminal.

There's also a light and a dark mode. The toggle sits in the top right, and a tiny script runs before the page is drawn, so you don't get a white flash if you prefer dark mode.

You don't need a framework for a personal site. Plain HTML and CSS get you surprisingly far.

What I learned

Building without a framework made me appreciate how much modern CSS can do on its own: grid layouts, custom properties for the colors and media queries for mobile all work fine without any extra tools. Next up is filling this blog with write-ups of my projects, so expect more posts soon.
